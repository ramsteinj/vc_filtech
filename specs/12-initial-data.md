# 12. 초기 데이터 (`initial-data/`) 적재 · 기대 결과 · 테스트 시나리오

> `initial-data/`는 **읽기 전용**. 적재는 파일을 MEDIA로 복사한 뒤 처리한다. 회사 자료는 모두 “SAMPLE · PoC 테스트용 가상 자료”, 입찰 공고는 실제 과거 공고(2010–2023)다.

## 1. 적재 명령

```bash
python manage.py load_initial_data [--mode skip|update] [--only company|bids] [--no-llm]
```
- 관리자 화면 버튼으로도 실행(`LOAD_INITIAL_DATA` Job).
- 멱등: `sha256`로 이미 적재된 파일은 skip(또는 update).
- `*:Zone.Identifier`, `.DS_Store`, `~$*`, 숨김 파일 무시.
- `--no-llm` 또는 LLM 미설정 시: 회사 자료는 규칙 추출로 완전 적재, 공고는 텍스트 추출·분류(규칙)까지만 하고 `processing_status=DRAFT`로 둔 뒤 LLM 설정 후 “추출 실행” 필요.

## 3. 입찰 공고 샘플 (`initial-data/bid_sample/`)

### 3.1 구조
```
bid_sample/
├── won/<폴더>/<첨부...>    → outcome = WON  (8건)
└── lost/<폴더>/<첨부...>   → outcome = LOST (현재 비어 있음 — 추후 추가 시 동일 규칙으로 적재)
```
- 폴더 1개 = BidNotice 1건, `source_ref = 폴더명`. 폴더명은 공고번호와 다를 수 있음(예: `20230342721` 폴더의 실제 입찰공고번호는 `20230323830-00`) → `notice_no`는 본문에서 추출.
- 폴더 내 파일 전부 BidAttachment. 공고문 분류 파일이 `is_primary`.
- 형식 분포: HWP 24, HWPX 1, XLS 2, XLSX 3, PDF 2(스캔 이미지 — 텍스트 0자).

## 5. 파서 테스트
- `bid_sample/**/*.hwp|hwpx|xls|xlsx` 전부 예외 없이 파싱, 추출 문자 수 > 100(산출내역서 등 소형 문서는 > 50).
