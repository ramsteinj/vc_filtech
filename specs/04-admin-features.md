# 04. 관리자 기능

모든 관리자 화면은 `/admin/*`, `role=ADMIN` 필요. 화면 상세는 [11](11-frontend.md).

## 1. 사용자 관리 — [03](03-auth-and-access.md) §5

## 2. 회사 자료 관리

### 2.1 회사 정보
- 단일 폼(회사명, 대표자, 사업자번호, 주소, 연락처, 중소기업 여부·확인서 유효기간, 나라장터 등록 물품분류번호 목록, 주요 제품, 소개).
- `company_profile` 문서 업로드 시 추출값을 **제안**으로 표시 → “적용” 클릭 시 반영.

### 2.2 제품 / 시험성적서 / 인증서 / 납품실적
각각 목록 + 상세 + 생성/수정/삭제.

| 엔티티 | 목록 컬럼 | 비고 |
|---|---|---|
| 제품 | 모델명, 형식, 치수, 등급(ISO16890/29461/EN1822), 정격풍량, 초기차압, 성적서 수 | 상세에서 연결된 성적서·실적 표시 |
| 시험성적서 | 성적서번호, 모델, 규격, 판정결과, 발행일, 폐지규격 여부, 공식인증 여부 | 제품 연결 드롭다운 |
| 인증서 | 인증번호, 인증명, 유효기간, 상태 배지(유효/만료임박/만료) | 만료 항목은 목록 상단 경고 |
| 납품실적 | 납품시기, 발주처, 사업명, 모델, 수량, 비고 | 발전소 여부 필터 |

### 2.3 입력 방법 (제품 정보 포함 모든 회사 자료)
1. **파일 업로드**: TXT, DOCX, HWP, HWPX, PDF (여러 개 동시 업로드 가능)
2. **Text 직접 입력**: 텍스트 영역에 붙여넣기
3. **수동 폼 입력**: 문서 없이 엔티티를 직접 생성

파일/텍스트 입력 후 처리 흐름:
```
업로드 → 텍스트 추출 → 문서 분류(자동, 수정 가능) → 메타데이터 추출(분류별 스키마) → [검토 화면] → 도메인 엔티티 생성/갱신
```
- 검토 화면: 좌측 문서 미리보기(추출 텍스트, PDF는 원본 뷰어), 우측 메타데이터 표(키·값·원문·근거 인용·신뢰도·출처). 신뢰도 < `extraction.low_confidence_threshold`(0.7)인 값은 노란색 강조.
- 매핑 결과(예: “Product FT-VB500 갱신 예정: 초기차압 130 → 130, 변경 없음”)를 diff로 보여주고 “적용”.
- 동일 키(모델명, 성적서번호, 인증번호)가 이미 있으면 **갱신**, 없으면 **생성**.

### 2.4 메타데이터 CRUD
- 문서별 메타데이터 행 추가/수정/삭제. 수정한 행은 `is_locked=True` → 재추출해도 유지. “잠금 해제” 가능.
- **문서 분류(MetadataSchema) 관리**: 분류 추가/수정/비활성화, 필드 정의(키, 라벨, 타입, 단위, 필수, 설명, 예시) 편집, 파일명 패턴 편집. 변경 후 “이 분류의 문서 재추출” 일괄 작업.
- 문서 재분류: 분류 변경 시 메타데이터 재추출 여부 확인.

## 3. 입찰 공고 관리

### 3.1 공고 등록
- 신규 공고 생성 시 입력 방법:
  1. **파일 업로드**(TXT, DOCX, HWP, HWPX, PDF + 첨부용 XLS/XLSX) — 여러 파일을 한 번에 드래그&드롭. 공고문 1개 + 첨부 N개.
  2. **Text 직접 입력** — 공고 본문 붙여넣기 (+ 파일 첨부 추가 가능)
- 업로드한 파일은 자동 분류([02](02-data-model.md) §3 BID 분류)되고, 공고문(`bid_notice`)으로 분류된 파일이 `is_primary`. 관리자가 변경 가능.
- 공고에 **첨부 추가/삭제/순서 변경/분류 변경** 가능.

### 3.2 추출
“추출 실행” → `EXTRACT_BID` Job:
1. 모든 첨부 텍스트 추출 (스캔 PDF 처리 포함)
2. 첨부별 메타데이터 추출 (분류 스키마 기준)
3. **공고 통합 추출**: 공고 메타데이터(공고번호, 공고명, 수요기관, 일정, 금액, 입찰방법, 자격 …), 품목(BidItem), **핵심 요구사항(BidRequirement)** — 모든 첨부를 합쳐서 추출, 요구사항마다 출처 첨부·페이지·인용 저장
4. 적합도 계산 + 품목별 후보 제품 매칭 ([08](08-compliance-evaluation.md) §6)
5. (설정 `bid.auto_evaluate_after_extract`=true면) 판정 Job 연쇄 실행

### 3.3 공고 수정
- 공고 메타데이터 폼 편집(수정 필드 잠금).
- 품목 표 편집(추가/수정/삭제).
- **핵심 요구사항 편집**: 카테고리·제목·요구 내용·정규화 값(JSON 고급 편집 + 카테고리별 간이 폼)·필수 여부·출처. 추가/삭제/순서 변경.
- 메타데이터(첨부별) CRUD — §2.4와 동일 UI.
- 낙찰 결과(outcome) 지정.
- 공고 삭제: 첨부·요구사항·판정·초안 모두 삭제(확인 대화상자, 공고명 입력 확인).

## 4. LLM 설정 (`/admin/settings/llm`)

- 제공자 선택: **ChatGPT(OpenAI) / Claude(Anthropic) / Gemini(Google)** 라디오. 활성 제공자는 하나.
- 제공자별 API Key 입력(password 필드, 저장 후 `••••abcd`로 표시, “변경” 버튼으로 재입력), Base URL(선택).
- “연결 테스트” 버튼: 해당 키로 최소 요청 → 성공/실패 메시지, `last_verified_at` 갱신. **저장 시 자동 테스트**하되 실패해도 저장은 가능(경고).
- 모델 선택 드롭다운: `LLMModelOption` 중 활성 제공자의 활성 모델. 기본값 Claude = `claude-opus-5-5`.
  - 모델 목록 관리: 추가(모델 ID 직접 입력)/수정/비활성화/기본값 지정. Claude seed: Opus 5.5(기본), Fable 5.1, Sonnet 5.5, Haiku 4.5 ([07](07-llm-integration.md) §3).
- 공통 파라미터: temperature, max_output_tokens, timeout, max_retries, 작업별 override(JSON 편집기 + 간이 폼).

## 5. 프롬프트 · 튜닝 설정 (`/admin/settings/prompts`, `/admin/settings/tuning`)

- **프롬프트 템플릿**: 키별 목록 → 편집(system prompt, user prompt template, output JSON schema, 메모). 저장 시 새 version 생성, 이전 버전 목록·diff·롤백. 사용 가능한 변수 목록 표시. “기본값으로 복원”.
- **프롬프트 테스트**: 템플릿 + 샘플 입력(문서 선택 또는 텍스트)으로 실행하여 원시 응답·파싱 결과 표시(저장 안 함).
- **튜닝 설정(AppSetting)**: 그룹별 폼. 각 항목 설명·기본값 표시, “기본값 복원”.
- 모든 설정은 PostgreSQL에 저장되며 변경 즉시 반영(캐시 사용 시 저장 시 무효화).

## 6. 운영 도구

- 작업(Job) 목록: 상태·진행률·오류, 재시도/취소.
- LLM 호출 로그: 작업·모델·토큰·지연·상태 필터, 응답 원문 보기.
- 초기 데이터 적재: “initial-data 다시 적재” 버튼(이미 존재하는 항목 건너뜀/갱신 옵션) ([12](12-initial-data.md)).
