# 00. 개요

## 1. 목적

(주)필텍(산업용 공기필터 제조사)의 입찰 업무를 지원한다.

1. 입찰 공고(공고문 + 규격서/시방서 + 물품명세서 등 첨부) 를 등록하면 **핵심 요구사항을 자동 추출**한다.
2. 회사의 **제품 사양서 · 시험성적서 · 인증서 · 납품실적**과 요구사항을 비교하여 항목별로 **충족 / 보완 필요 / 확인 필요**를 판정하고, 판정 근거와 자동 답변을 만든다.
3. 공고별 **적합도**를 계산하여 회사 제품에 맞는 공고를 우선 보여준다.
4. **Compliance Matrix, 입찰 체크리스트, 발주처 기술질의서, 검토 보고서(PDF)** 초안을 생성하고, 담당자가 수정한다.

## 2. 사용자

| 역할 | 설명 | 주요 화면 |
|---|---|---|
| 관리자 (ADMIN) | 시스템 설정, 회사 자료·입찰 공고 관리, LLM 설정, 사용자 관리 | `/admin/*` |
| 입찰담당자 (BID_MANAGER) | 공고 검토, 판정 수정, 초안 작성·다운로드 | `/`, `/bids/*` |

관리자는 입찰담당자 화면도 모두 사용할 수 있다.

## 3. 핵심 흐름

```
[관리자] 회사 자료 업로드 ─▶ 텍스트 추출 ─▶ 문서 분류 ─▶ 메타데이터 추출 ─▶ 검토/수정 ─▶ 제품·성적서·인증·실적 DB
[관리자] 입찰 공고 + 첨부 업로드 ─▶ 텍스트 추출 ─▶ 공고 메타데이터 + 품목 + 핵심 요구사항 추출 ─▶ 적합도 계산
[담당자] 대시보드 ─▶ 공고 클릭 ─▶ ①요구사항 ─▶ ②회사 자료 비교 ─▶ ③판정·답변(수정) ─▶ ④초안 생성 ─▶ ⑤확인·수정·PDF
```

## 4. 용어집

| 용어 | 정의 |
|---|---|
| 입찰 공고 (BidNotice) | 하나의 입찰 건. 공고문과 여러 첨부파일로 구성 |
| 첨부 (BidAttachment) | 공고에 딸린 파일: 공고문, 규격서(한난물자규격서, 구매규격서, 시방서), 물품명세서/구매내역서, 계약 특수·일반조건, 계약이행능력심사 기준, 제한경쟁사유서, 도면, 산출내역서 등 |
| 품목 (BidItem) | 공고 내 구매 대상 하나 (예: Pre Filter 594×594×95, 1,815 EA) |
| 핵심 요구사항 (BidRequirement) | 판정 단위. 카테고리: 제품 치수, 필터 형식, 필터 등급, 효율, 차압, 풍량, 재질, 시험규격, 인증/자격, 납품실적, 납기, 제출서류, 품질보증/하자, 기타 |
| 판정 (Verdict) | `MET`(충족) / `NEEDS_SUPPLEMENT`(보완 필요) / `NEEDS_CONFIRMATION`(확인 필요) |
| 근거 (Evidence) | 판정을 뒷받침하는 회사 자료(문서·페이지·인용) 및 공고 원문 인용 |
| 적합도 (Fit Score) | 0–100. 공고가 회사 제품군·자격에 얼마나 맞는지 |
| 확인 / 미확인 | 입찰담당자가 해당 공고 검토를 완료(“확인 완료” 버튼)했는지 여부 |
| 낙찰 결과 (Outcome) | `WON` / `LOST` / `PENDING` / `NOT_BID`. 과거 공고 학습·참고용 |

## 5. 범위

### 포함
- 입력 형식: **TXT, DOCX, HWP(5.0), HWPX, PDF(텍스트)** — 필수. 공고 첨부에는 **XLS/XLSX**도 허용(실제 공고에 물품명세서가 엑셀로 옴).
- 스캔 PDF(텍스트 없음): LLM 문서 입력(멀티모달)으로 처리, 미지원 시 `OCR 필요` 상태로 표시 ([06](06-document-processing.md)).
- LLM: OpenAI(ChatGPT), Anthropic(Claude), Google(Gemini) 중 택1.
- PDF 보고서 다운로드.

### 제외 (현 단계)
- 나라장터 등 외부 사이트 자동 수집(크롤링) — 향후 과제로 [13](13-roadmap.md)에 기록.
- 입찰 가격 산정, 투찰.
- 구형 `.doc` 바이너리(LibreOffice가 설치된 경우에만 변환 지원, 선택 기능).

## 6. 비기능 요구사항

- UI 언어: 한국어. 반응형(데스크톱 우선, 1280px 기준).
- 동시 사용자 10명 이하 사내 시스템 가정.
- 업로드 파일 1개 최대 50MB (설정 가능).
- LLM 작업(추출·판정·초안)은 백그라운드 작업으로 실행하고 진행 상태를 표시 ([01](01-architecture.md) §5).
- 모든 생성물은 "초안"이며 최종 제출 전 담당자 검토 필요 문구를 표시.
- 감사 추적: 판정·답변·초안 수정 시 수정자·수정시각 기록.

## 7. 결정 사항 (Decision Log)

| # | 결정 | 이유 |
|---|---|---|
| D1 | 사용자 모델은 단일 `User(AbstractUser)` + `role` | 요구사항 "AbstractUser 상속 확장", 권한 분기 단순화 |
| D2 | 판정은 규칙 엔진 우선, LLM 보조 | 수치 비교의 재현성·신뢰성 확보 |
| D3 | “확인 건수” = 담당자가 `확인 완료` 처리한 공고 수 | 단순 열람과 검토 완료를 구분 |
| D4 | 판정은 3단계 유지, 치명적 미충족은 `보완 필요` + `risk=HIGH` | 요구사항의 3분류 유지하면서 입찰 불가 위험 표시 |
| D5 | 백그라운드 작업은 DB 기반 Job 큐 + `run_jobs` 워커 | Redis/Celery 없이 단순 운영 |
| D6 | 인증은 JWT(SimpleJWT) | SPA와 API 분리 |
| D7 | 공고 첨부로 XLS/XLSX 허용 | 실제 공고 샘플에 엑셀 명세서 포함 |
| D8 | DB는 로컬 설치 PostgreSQL 18 사용, docker compose·Dockerfile 등 Docker 미사용 | 개발 환경에 PostgreSQL 18이 5432에서 이미 동작 중 (사용자 결정, 2026-10-05) |
